# DecisionTrace 教师演示脚本(重定位版)

> 总时长约 10 分钟;文末附 5 分钟精简版。演示数据是 `seed_demo.py` 构造的
> 完整故事(两个小组、三周活动),每一步的预期结果都**确定性**可复现。

## 开场(40 秒)

> 「DecisionTrace 是架在**导师和学员项目组之间**的决策透明层。学员把组会
> 讨论贴进来,系统抽出决策候选,人在唯一的门槛上确认;确认后的决策会
> 长成**决策链** —— 一条链一个议题,讨论就在每个决策点下面,修订就是
> 链上的新节点。链提交给导师,导师**逐点批注、逐点裁决** —— 认可一个
> 点,链就锁定,这个点进入执行阶段:任务、拓扑排序、AI 检查。一句话:
> **学生讨论决策,导师选择决策,系统监督执行。**」

三个关键词:**讨论成链、认可即选择、执行始于认可**。

## 准备

1. 启动后端(`backend/.venv/Scripts/python -m uvicorn app.main:app --port 8000`)
   和前端(`npm run dev`,浏览器打开 `http://localhost:5173`)。
2. 数据复位(每次演示前):

```bash
cd backend && .venv/Scripts/python seed_demo.py
```

3. 界面语言:全程中文界面(演示数据本身为英文会议文本,含一条中文组会)。

---

## 场景 1 · 输入即数据(60 秒)

**操作:** 侧边栏 → 「收集与审核」 → 指给老师看现有 4 条讨论(其中一条
中文组会)→ 新建讨论,粘贴一段组会文本:

```
Alice decided to use Vue for the dashboard because the team already knows it. Bob will build the dashboard by 2026-12-15.
```

→ 「保存讨论」 → 「抽取候选」。

**预期:** 一条候选:带决策人 Alice 的**决策** + 来源句高亮。Bob 的
任务句**不产生候选** —— 任务不是从文本抽的,它们来自被认可决策链的
执行阶段。

**操作:** 指给老师看「只看我的」筛选和每个人名的**颜色**。

**要说:** 「没有表单要填 —— 讨论文本就是输入。抽取只产**决策候选**,
带原文句子,人确认才落地。每个决策人都有一贯的颜色,'只看我的'就是
**谁说谁审**。任务不靠猜 —— 导师认可决策之后,任务在链上讨论里自然
产生,再挂到被认可的点上。」

## 场景 2 · 决策链:讨论、修订与提交(120 秒)

**操作:** 侧边栏 → 「决策链」 → 点开 `#1 Use PostgreSQL`(已认可)。

**预期:** 链上有两个决策点:**PostgreSQL(已认可)** 和
**SQLite(已否决)** —— 认可即选择:导师选 PostgreSQL 时,团队的
SQLite 修订被自动否决,完整保留在链上。每个节点下都有自己的讨论
线程(Bob 质疑 → Alice 回应 → 众人附议),导师批注挂在 PostgreSQL
节点上。

**操作:** 点开 `#4 Use Tailwind for styling`(讨论中)→ 在节点下用
「署名 + 留言」发一条讨论;再演示「下一个决策」表单(输入修订标题)。

**要说:** 「一条链一个议题。修订不覆盖历史 —— 它是链上的**新节点**,
旧节点永远可读。讨论不是聊天室:每句话挂在自己关心的那个决策点下面,
导师一眼看到每个点的完整理由。」

**可选加分:** `#2 Build a web app` 链演示「挂起后修订再提交」的完整故事:
导师挂起 → 团队补小程序对比 → 追加节点 → 重新提交。

## 场景 3 · 导师:整链审阅 + 逐点裁决(150 秒,核心)

**操作:** 侧边栏 → 「待确认的决策」。指给老师看:两个小组分组展示,
组名加粗。`#2 Build a web app` **整条链已内联展开**:

- 决策点 1 `Build a web app`(挂起)+ 导师批注「下次组会带小程序对比」
- 决策点 2 `Build a WeChat mini program first`(待确认)+ Carol 的对比结论

**操作(重点):**

1. 在**决策点 1** 的操作条:输入批注「网页版覆盖面更广,先做网页版」→
   点「**认可**」。
2. 观察:**决策点 2 自动变「已否决」**(认可即选择 —— 导师选了更早的
   那个点,修订被否决);整条链离开待确认。
3. 切到「决策」视图:链上被否决的点**从决策表消失**(导师已裁决);
   链视图里历史仍在,判定芯片清清楚楚。

**要说:** 「导师看到的是**整条链**,不是一张标题卡片 —— 每个点、
它下面的讨论、已有批注,全都在。批注和裁决都落在**具体决策点**上,
而且**认可是选择**:导师可以选链上任意一个点,不一定是最新的;选定
一个,其余的点被否决,链锁定 —— 执行中的决策不能再变。一条链永远
只有一个点在执行,不可能出现互相矛盾的决策同时开工。」

## 场景 4 · 执行:任务、拓扑序与 AI 检查(120 秒)

**操作:** 侧边栏 → 「划分任务承诺」 → 选择器里是**已认可的决策点**
(`Use PostgreSQL`)→ 指给老师看 5 个任务;演示「添加任务」。

**操作:** 切到「拓扑排序图」 —— 分层 SVG 图:Carol(已完成)→ Bob
(进行中)→ Eve / Dora / Frank。

**操作:** 切到「问题」 —— AI 检查报告:**乱序**「Build the login page
(Dora)在 Bob 完成前就开始了」;指给老师看节点的等待/就绪/阻塞状态
是**实时算出来的**。

**操作:** 导师侧 「进行中的决策」 → 按组选择、同样的拓扑图**只读**。

**要说:** 「执行**只属于被认可的决策** —— 没被认可的点根本不会出现
在任务视图里。拓扑顺序、节点状态、乱序检查都是读的时候算出来的,
不是人填的。导师看的是同一块板子,只读 —— **学生划桨,导师掌舵,
系统盯着桨有没有划反**。」

## 场景 5 · 编号、双组与全貌(60 秒)

**操作:** 快速切换右上角项目到 `Campus Navigation App`:
决策表是 `#2-1 Use Mapbox`,链卡片是 `#1 React Native / #2 Mapbox` ——
**编号按项目重新开始**。再切回主项目,展示「决策」视图按链分组、
`#1-2` 式编号、链外决策 `#1 / #2`。

**要说:** 「编号是**项目内**的:链 `#1..#N`,链上节点 `#链号-节点号`,
独立的决策 `#1..#M`。第二个组的第一个决策就是 1,不会顶着 7、8
的全局编号 —— 数据库 id 永远不出现在界面上。」

## 收尾(30 秒)

> 「这就是重定位后的 Part II。系统回答了三个问题:**为了谁**(导师一对
> 多监督)、**连接什么**(讨论→候选→决策→链→裁决→执行,一条线)、
> **哪些决策值得提取**(带决策人的决策句,人把关)。Part III 会用评估
> 协议验证抽取管线,并补上登录与重新开链等开放项。」

## 5 分钟精简版

1. 开场定位(30 秒)
2. 场景 1:粘贴 → 抽取 → 候选人颜色(60 秒)
3. 场景 3(核心):待确认内联链 → 逐点批注 → 认可一点否决另一点(120 秒)
4. 场景 4:任务 → 拓扑图 → 乱序检查 + 导师只读板(90 秒)
5. 场景 5 编号 + 收尾(30 秒)

(场景 2 的讨论与修订改为口头带过。)

## 功能覆盖清单

| 功能 | 场景 |
|---|---|
| 讨论录入(粘贴/导入、EN+ZH) | 1 |
| 决策抽取 + 候选审核(来源句、决策人、颜色、只看我的) | 1 |
| 决策链(节点保留、逐节点讨论、追加修订、提交) | 2 |
| 导师整链内联审阅 | 3 |
| 逐节点批注 / 认可 / 待定 / 否定 | 3 |
| **认可即选择**(否决其余、链锁定、从决策表消失) | 3 |
| 执行仅限已认可决策点(任务、拓扑图、乱序检查) | 4 |
| 导师只读进度板(按组按决策点) | 4 |
| 项目内编号(链/节点/独立决策) | 5 |
| 双组演示数据(seed_demo.py) | 全程 |
